# Output inventory workload

`OutputInventoryJobRunner` creates a fixed, namespace-bound, one-shot Job that invokes `agent-sandbox-output-inventory` against one exact `artifacts-<run>` PVC. The caller supplies the claimed task, reviewed binding, exact completed Sandbox handle, approved `OutputInventoryRequest`, and fresh PVC UID. The request must use `/artifacts`; its selected paths remain in an immutable Secret and never appear in Job metadata or runner receipts.

The total runner deadline starts before journal/create work and includes the Job deadline plus a fixed startup grace, so delayed create, guard, or observation calls cannot escape it. The operator config supplies the pinned image, runtime class, pool selector, resource/deadline limits, private journal root and writer UID. Before each create, the runner reserves and fsyncs a private journal intent. It creates only the paired deny-all NetworkPolicy, immutable request Secret, and Job. A fixed non-root init container uses the same resource requests and limits as the inventory helper, then copies `request.json` from the projected Secret into a private memory-backed `0700` directory with a `0600` file. The writable init mount omits `readOnly`, matching Kubernetes readback; the inventory container mounts the whole request memory volume read-only at the same `/request` path and opens its owned `/request/private` child, alongside the read-only output PVC. It has no service-account token, host path, writable PVC, ingress, or egress.

The runner requires a guard before every create and observation. It verifies the exact output PVC UID and absence of active writable mounts before creating the Job and after parsing its result. It accepts only the created Job UID, one controller-owned succeeded Pod with the rendered runtime class, init container, inventory image, command, arguments, mounts, volumes, restricted security context, and terminated exit status, plus a bounded single-line versioned inventory whose measured metadata matches the approved selection. The three named volumes and every mount must exactly match the rendered read-only artifacts PVC, projected request Secret, and private memory directory; duplicate, extra, or alternate volume sources fail closed. Missing Job counters are pending state; explicit `Failed` or `FailureTarget` conditions fail closed. Replaced, partial, failed, ambiguous, paginated, or malformed observations fail closed.

This source does not authorize the PVC, establish writer exclusion, create a terminal export record, retain artifact bytes, delete workload objects, grant RBAC, or activate Kubernetes. The caller owns runtime/lease fencing and must preserve the original inventory bytes before any later terminal-export publication.

Kata does not support this memory-volume `subPath` handoff. Keep the same whole-volume mount path between init and runtime containers; require private ownership on the child descriptor root. With `subPath` the runtime container sees an empty root-owned mount, while the whole-volume form preserves UID 65532, directory mode 0700 and file mode 0600. See the [upstream storage limitation](https://github.com/kata-containers/kata-containers/blob/main/docs/Limitations.md).
